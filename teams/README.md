# Teams

One folder per team.

## Getting set up

1. Fork the repository to your own GitHub account.
2. Create your folder here: `teams/your-team-name/` — short, lowercase, hyphenated (`nova-alpha`, `meridian-beta`).
3. Create these four subfolders inside it:

   ```
   teams/your-team-name/
     demo/     the working code
     docs/     notes, decisions, and your write-up on what surprised you
     deck/     your 8-10 slide deck (commit the file, not a link)
     video/    your 5-minute walkthrough, or a link to it in a README here
   ```

4. Put a README at the top of your folder with your team name, your scenario, your members, and how to run the demo.
5. **Open a draft pull request early**, while the work is still rough. That is how you get feedback in time to use it.

## A few things worth knowing

**The demo must run from a clean checkout** by someone who was not on your team and has nothing set up. Write the README for that person.

**The video is the artefact most likely to be shown to someone outside the project.** Show the before-and-after side by side — that contrast is the whole point.

**The write-up on what surprised you is a real deliverable**, not an afterthought. What was harder than expected? What was easier? What did you assume that turned out to be wrong? Honest observations there are more interesting than a polished summary.

Keep your changes inside your own folder. Don't edit another team's work.
